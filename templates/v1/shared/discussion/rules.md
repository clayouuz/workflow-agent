# 讨论规则

## 阶段依赖
- 阶段顺序：讨论方案设计 → 确认修改方案 → 讨论代码设计 → 确认代码设计 → 实现
- 后一环节的开始依赖前一环节完成

## 方案设计
- 方案设计阶段不涉及代码
- 方案展示必须让用户明确"确认"或"修改"
- 任务足够简单且方案足够明确时，直接展示代码设计，一次确认后进入实现

## 代码设计
- 引导用户向好的代码设计模式靠近
- 代码设计必须包含：具体修改地点、修改的代码内容、注释
- 细节不明确时，用提问方式向用户确认，不自行猜测
- 复杂任务输出设计文档到 ledger/designs/<Bid>-design.md；涉及 Cocos 场景编辑（生成/修改 .scene、.prefab、节点、组件）时，按 ledger/designs/template-cocos-scene.md 填写；简单任务可跳过设计文档

## 工具使用
- 已有工具能完成的任务，优先使用工具
- 已有工具能力不足时，提出 tool request
- 机械流程直接由模型做不稳定时，提出 tool propose

## 知识使用
- agent 主动将项目级知识（文档位置/固定约定/关键结论）直接写入 knowledge/index.md，默认通过
- add 前由 agent 自行读取 index.md 查重，已存在则不重复加入
- 用户只做拒绝式审批：不满意时执行 knowledge remove 删除
- 只入跨任务复用的事实、用户确认的约定、指向真实存在文件的位置；禁止猜测
- 每条知识必须带来源与日期

## 台账报告
- 每次台账变更后，用一句话明文报告
- 格式示例：新增知识：xxx / 完成任务：B1-S2 / 验收通过：B1 / 状态转移：B1 in_progress → done / 编译快照：B1
