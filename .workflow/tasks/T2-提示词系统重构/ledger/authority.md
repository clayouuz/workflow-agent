# 权威说明文档

## 任务目标
重构 workflow-agent 的提示词与上下文系统，为每次会话提供精确、精简、可恢复的上下文。

## 当前有效结论
- 核心原则：不过度限制 LLM；只保留必要边界、当前事实和可选启发。
- 讨论阶段只记录精简检查点，不记录完整讨论过程。
- workflow-agent 管理的上下文以 6k–10k tokens 为常态参考、15k 为警戒参考、25k 为极限参考；只估算和提醒，不硬性限制。
- 废弃 `discussion/rules.md`，必要的通用规则合并到 `discussion/workflow.md`。
- 启发策略应主动补充与当前决策相关、用户可能缺乏的领域知识，不强制方案数量或思考形式。
- 历史事件格式为：`日期: 事件类型 | 内容 | 原因`。
- 历史归档使用确定性版本号，不使用随机 ID；归档路径由编译器生成并写入快照。
- `.workflow` 内的台账、知识、原始材料和检查点可先更新后通知；项目源码、配置、文档和资源须在方案及代码设计确认后修改。
- 挂起优先作用于 benchmark 内的 step；挂起 step 不自动使整个 benchmark 或任务阻塞。CLI 跳过挂起 step，后续工作由 Agent 根据依赖关系选择。
- `benchmarks.md` 保存 step 状态，`history/` 保存挂起与恢复事件；`current.md` 保留挂起项的精简摘要，它是可再生成的热层索引，不是状态真相源。
- 核心台账采用单一职责：`authority` 记录已确认的任务契约，`benchmarks` 记录可验收结果与工作状态，`designs` 记录已确认的实现与验证方案，`verification` 记录实际验证证据。
- benchmark 状态使用 `pending | in_progress | blocked | done | obsolete`；删除 `revised`，修改作为历史事件记录。
- 验收标准区分 `[auto]` 与 `[manual]`；自动覆盖检查精确到验收项 ID，不只检查 benchmark ID。
- 新增通用设计模板；Cocos 模板作为可独立加载的完整特化模板，核心模板不包含 Cocos 知识。
- knowledge 只保存跨任务可复用的事实，分为“路径与资源 / 文档入口 / 项目约定”；条目不写来源和日期，变更追溯放入 audit。
- 验证流程为：实现前定义黑盒期望并写测试，实现后根据代码补充白盒测试，运行影响测试与全量测试，无法自动验证时给出用户自测流程并记录结果。
- 测试结果保存执行证据和源码/测试文件内容指纹，验收时检查结果仍对应当前文件。
- 提示词分为四层：`SKILL.md` 只作操作入口，`workflow.md` 只定义协作阶段与边界，`context.md` 只定义上下文选择与估算，`strategy.md` 只提供非强制启发。
- `current.md` 同时作为精简的上下文引用清单；支持 `文件#标题` 的段落级加载，Agent 选择语义上需要的内容，CLI 只负责确定性提取、估算和记录。
- 上下文估算只提供字符数、近似 token 数和主要来源提醒；不自动压缩、不拒绝加载。
- 工作区引入结构版本和显式迁移；迁移可自动替换未修改的旧模板，已自定义文件保留原件并生成新版候选，废弃的 `rules.md` 归档且可恢复。
- 新工作区不生成示例 benchmark 和会污染项目全量结果的 smoke tests；示例只作为 workflow-agent 自身测试夹具。
- benchmark 验证证据状态为 `valid | failed | stale | incomplete`；没有测试、没有覆盖或执行中断都不算通过。
- `ledger accept` 默认检查验证证据；用户可显式 override 并记录原因。
- 提示词效果初期使用固定 Agent 场景人工验证，暂不建设自动模型评测系统。
