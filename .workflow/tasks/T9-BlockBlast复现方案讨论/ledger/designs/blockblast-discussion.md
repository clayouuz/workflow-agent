# Block Blast 复现方案讨论

## 目标
在用户指定的 Block Blast 参考版本和运行环境基础上，复现可观察的核心流程、棋盘规则、方块操作、消除反馈、失败/重开流程和必要的界面表现。当前先完成方案讨论，不假定缺失的玩法数值或视觉细节。

## 具体方案
1. 先确认权威参考：版本、平台、可运行入口、允许采集的截图/录像/操作证据，以及目标是核心玩法切片还是完整流程。
2. 以证据为准建立最小规则清单和验收条目，再拆分首个可验收 Benchmark。
3. 技术上保持 Domain（棋盘与规则）、Application（回合/输入用例）、Presentation（Cocos 棋盘与反馈）、Infrastructure（时间、随机、存档）分层；Domain/Application 不依赖 Cocos 类型。
4. 先做确定性棋盘竖切片，再按参考证据扩展方块池、消除连锁、分数、失败、重开和外围 UI；每个切片单独自动验证并在最终候选上做 Cocos 预览验收。

## 验收方式
- 参考版本、范围和未覆盖项有明确记录。
- 相同初始棋盘、方块序列和操作能得到相同的占用、消除、分数和终局结果。
- 自动断言覆盖合法/非法放置、行列或区域消除、连续消除、无路可走、重开和状态清理；Domain/Application 不导入 `cc`。
- Cocos 预览中检查棋盘布局、拖放/点击输入、消除反馈、分数/终局 UI、重开流程和控制台错误。
- 每个 Benchmark 保存自动结果、浏览器观察、截图/日志和与参考差异；未取得用户验收前不标记完成。

## 待用户确认
- 目标参考版本与平台。
- 复现范围：核心玩法竖切片或完整产品流程。
- 是否已有参考包、录像、截图或可操作页面。
- 首个 Benchmark 优先级：棋盘放置/消除，还是先做整体 UI 流程。
