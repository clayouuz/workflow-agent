# 权威说明

## 目标
将错误进入核心工作流的 Cocos 特化内容拆成按任务启用的可选包，并把固定的 Laya→Cocos Agent 场景还原为通用语义迁移能力。

## 范围
- 新工作区默认只生成通用设计模板，不生成 Cocos 文件。
- Cocos 设计模板作为任务级可选特化包保留。
- 核心 Agent 场景只验证跨系统语义迁移；Laya→Cocos 案例归入 Cocos 特化评测。
- 通过 v3 模板与迁移支持现有 v2 工作区。

## 非目标
- 不改变 TypeScript 验证能力；项目有 TypeScript 支持即可。
- 不修改上下文预算、验证状态模型、工作流阶段或授权边界。
- 不删除或削弱 Cocos 特化模板本身。
- 不建设基于关键词的项目类型自动识别。

## 已确认要求
- 核心初始化只生成通用设计模板。
- 任务明确涉及 Cocos 时，可在 `.workflow` 内启用 Cocos 特化包并通知用户。
- 特化包启用由 Agent 明确决定，不通过关键词自动猜测；重复启用必须幂等，其他任务不受影响。
- 核心场景使用通用“跨系统语义迁移”，检查单位、原点、方向、层级、默认值等差异，不出现 Laya 或 Cocos。
- Laya→Cocos 的坐标、锚点等案例只存在于 Cocos 特化评测。
- v2 是不可变基线，语义变更通过 v3 发布。
- v2 未修改的官方 Cocos 模板从普通任务目录移出并可恢复归档；用户自定义过的 Cocos 模板原样保留。
- 新工作区默认不含 Cocos 文件；迁移重复执行结果一致，失败时回滚。

## 必须遵守的约束
- `.workflow` 台账可先更新再通知；项目源码、模板、测试和文档须在代码设计确认后修改。
- 实现前先写黑盒失败测试，实现后补白盒测试并检查实际结果。
- 模板语义变化必须提升结构版本，不修改已发布的 `templates/v2/`。
- 注释只解释兼容、迁移和反直觉原因。
