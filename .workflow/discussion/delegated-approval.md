# 审批委托模式

只有用户明确将阶段审批委托给 Agent，且当前任务 `ledger/authority.md` 已记录委托状态和范围时，才应用本文件。默认审批流程仍由 `discussion/workflow.md` 定义。

## 启用前的边界讨论
- 讨论当前任务的自动审批范围、不可自动审批事项、用户验收和重新讨论条件；只记录与当前任务相关的内容，不机械照抄通用分类。
- 用户只表达笼统委托时，先展示任务特定边界并等待用户确认；确认前不标记为已委托，也不加入本文件的上下文引用。
- 用户已经把边界说明明确时，复述授权范围和排除事项后直接启用，不要求重复确认。
- 委托确认后，在 `ledger/authority.md` 精简记录状态、自动审批范围、不可自动审批、用户验收、重新讨论条件和授权依据。
- 后续目标、范围或验收方式发生实质变化时，只重新讨论受影响的边界，其余授权继续有效。

识别不可自动审批事项时，检查任务是否涉及目标或范围变化、需要用户作关键取舍、高影响或不可逆外部操作、验证风险接受，以及 Agent 无法可靠完成的人工或视觉验收；没有命中的类别不写入任务记录。

## 强制讨论与确认
- Agent 仍须完成并审查方案、代码设计和验证设计；设计不充分时先自行修正，但自审不能代替用户确认。
- 委托只改变设计质量的审查责任，不取消用户参与讨论和明确确认。创建任务、启用委托、填写设计或 Agent 自审通过都不构成讨论完成。
- 实际方案必须向用户展示并取得明确确认，随后实际代码设计也必须展示并取得明确确认，状态机才允许实现。
- 简单任务可以合并展示方案和代码设计，但仍须取得一次针对已展示内容的明确确认。
- discussed 状态记录设计文件与内容哈希；confirmed 状态记录用户确认原文。设计实质变化后旧确认失效并退回讨论状态。
- Agent 必须在修改项目源码、配置、文档或资源前执行 `ledger delegation permit`；没有 `implementation_permitted` 不得实现。
- 委托默认只属于当前任务，不继承到其他任务；用户可以缩小范围或随时撤销。

## 必须暂停
- 目标或范围存在会实质影响结果的歧义。
- 工作需要扩大已委托范围。
- 涉及不可逆删除、外部发布、真实费用、账号权限、敏感数据或其他高影响操作。
- 验证依赖只有用户才能可靠观察的界面、设备或主观体验。
- 验证缺失、失败或过期，需要用户接受风险或执行 `ledger accept --override`。
- 所有可继续的步骤均已阻塞。

## 验证边界
- 审批委托是实现授权，不是验收证据；不得据此填写 `test manual ... pass`。
- 预览效果应先完成可自动验证部分，再集中提供环境、操作步骤和可观察预期，请用户验收。
- 等待用户验收时只挂起对应 step；无依赖的其他工作继续推进。
- 用户反馈失败后可在原委托范围内直接修复；反馈实质改变目标或范围时重新确认。
