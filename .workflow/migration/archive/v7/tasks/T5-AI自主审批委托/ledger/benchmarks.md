# Benchmark 清单

每个 benchmark 描述一个可独立验收的结果。验收项使用唯一 ID，并标记 `[auto]` 或 `[manual]`。

## B1 可选审批委托上下文 【in_progress】
自主审批作为默认关闭的任务级增量特性；常规任务不加载委托规则，显式委托后才持久化并装配。

### 验收标准
- [ ] B1-A1 [auto] 常规任务的上下文不包含审批委托规则，原有 workflow 内容保持不变
- [ ] B1-A2 [auto] 显式记录委托并加入引用后，ledger load 精确装配独立审批委托文件
- [ ] B1-A3 [auto] 新任务默认常规模式，不继承其他任务的审批委托
- [ ] B1-A4 [manual] Agent 在委托范围内自主通过阶段审批、通知后继续，并在越权或用户专属验证时暂停

### 步骤
- [x] B1-S1 先编写并运行旧实现下失败的黑盒测试
- [x] B1-S2 新增可选委托模板并更新 Agent 操作入口
- [x] B1-S3 补充固定 Agent 行为场景并检查提示词边界

## B3 委托边界检查点 【in_progress】
委托模式启用前完成一次任务特定边界讨论；边界明确后减少后续等待，同时不增加常规任务负担。

### 验收标准
- [ ] B3-A1 [auto] 委托规则要求记录自动审批范围、不可自动审批事项、用户验收和重新讨论条件
- [ ] B3-A2 [auto] 笼统委托与已明确边界的委托采用不同推进方式，常规任务行为不变
- [ ] B3-A3 [auto] v4 工作区迁移后原 workflow、authority 状态和可选加载语义保持不变
- [ ] B3-A4 [manual] Agent 能在委托讨论中主动识别任务特定的不可自动审批事项，后续仅命中边界时暂停

## B4 委托讨论状态机 【in_progress】

- [ ] B4-A1 [auto] 委托任务没有完整讨论与用户确认链时不能取得实现许可
